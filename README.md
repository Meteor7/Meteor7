## 企业 CRM：从送片验证到客户资料归档

**场景**：半导体设备客户会先寄送晶圆（Wafer）进行 Demo 验证，再根据测试结果评估采购。通用 CRM 难以适配这套流程，定制成本较高，客户资料也容易分散。

- **需求与方案**：对接销售工程师和管理层，梳理角色分工、业务流程与管理指标，主导系统从 0 到 1 建设。
- **Demo 流程**：实现申请、工程师评审、管理层审批、送片与测试准备、测试记录、报告及客户反馈，支持复测轮次和历史记录追溯。
- **客户与管理看板**：集中管理客户、联系人、商机和跟进记录，关联 Demo 与测试资料，按管理层需求建设销售数据看板。
- **开发与质量**：使用 Codex、图像模型快速确认原型，明确接口契约，再借助 Claude Code 实现功能；同事协助后端与数据库审查调试，在测试与审查中发现并修复越权和重复审批问题。
- **实际交付**：部署至公司内网 Linux，已供 **4 名销售、8 名工程师、3 名管理人员**使用，支持 Demo 进度查看、资料归档与维护留痕。

`Vue` · `TypeScript` · `Python` · `Frappe` · `MariaDB` · `Linux`

## ERP/OA：让发票信息进入报销流程

**场景**：财务与采购需要逐张手工录入发票，操作繁琐。系统整体覆盖审批、工时、请假和采购管理，我与另一位同事协作开发，主要负责发票识别与报销方向。

- **需求调研**：参与业务调研及 FAT 会议，与管理层对齐业务规则和功能需求。
- **识别与回填**：基于本地部署的 **PaddleOCR** 提取发票号码、日期、税额和金额等字段，经人工核对后生成报销明细。
- **业务校验**：支持发票查重、金额与关联状态校验，并保留必要的权限控制及操作记录。
- **实际使用**：已供财务及采购部门使用，每月处理 **100+ 张发票**，减少重复手工录入。

`Python` · `PaddleOCR` · `FastAPI` · `Frappe` · `Vue` · `Docker`

## DINA：学业诊断与知识点可视化

面向中学教师的学业诊断系统。访谈 **5 位一线教师**，围绕成绩归因与知识点追踪，独立实现 DINA 认知诊断模型，输出学生知识点掌握画像与班级薄弱知识点热力图。

借助 Claude Code 完成产品设计、前后端实现及测试，交付成绩分析看板和诊断报表，覆盖 **5 个班级、200+ 名学生**。
